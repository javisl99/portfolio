## Problema

BuildingCenter no era un entorno controlado de desarrollo. Era una plataforma SAP Commerce Cloud viva, con presión operativa real, flujos sensibles para negocio y visibilidad directa desde cliente.

Eso significaba que cada cambio debía equilibrar velocidad de entrega, estabilidad de plataforma, investigación rigurosa de incidencias y comprensión clara del impacto funcional.

## Solucion

- Desarrollé funcionalidad backend con Java, Spring y SAP Commerce Cloud sobre una plataforma ya activa en producción.
- Trabajé sobre servicios, modelos de datos, jobs, interceptors, validators, integraciones y lógica de negocio ligada al comportamiento core del sistema.
- Investigué incidencias, tracé causas raíz y participé en mejoras de estabilidad en lugar de tratar los tickets como casos aislados.
- Combiné Java, Spring y SQL para diagnosticar problemas complejos y apoyé debugging asistido por IA para acelerar análisis y acotar hipótesis con más rapidez.
- Colaboré directamente con negocio, QA y equipos funcionales para transformar requisitos e incidencias en acciones técnicas escalables.
- Usé flujos AI-Assisted para acelerar análisis técnico, debugging, documentación y tareas de ingeniería repetitivas, manteniendo siempre el criterio técnico final.

## Tech stack

Java, Spring, SAP Commerce Cloud, SQL, FlexibleSearch, integraciones enterprise, análisis de incidencias y flujos de AI-Assisted Development.

## Impacto

Este caso refleja mejor que ningún otro mi posicionamiento actual como Backend Software Engineer: alguien capaz de entregar funcionalidad, sostener producción, investigar problemas complejos, mejorar la estabilidad de la plataforma y comunicarse con soltura entre capas técnicas y de negocio dentro de una plataforma enterprise.
